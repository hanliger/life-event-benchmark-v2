# Life-Event Benchmark v4 — Korean Financial Dialogues

Synthetic Korean-language banking dialogues for a state-first financial life-event
memory benchmark. Each canonical session is a short customer–assistant conversation
tied to a point in one persona's simulated life trajectory.

- **Personas / trajectories:** 20 (`traj_001`–`traj_020`, one distinct `persona_id` each)
- **Canonical sessions:** 6,000 (300 per persona)
- **Counterfactual filler sessions:** 400 timeless reserve dialogues (20 per persona)
- **Generator:** `claude-sonnet-5` (provider: Anthropic)
- **Run:** v4; counterfactual filler contract: `counterfactual-filler-v1`

> The `gold` config is the benchmark answer key. Keep it separated from evaluated
> model inputs.

## Canonical dialogue layout

The answer-free dialogues and their labels are split into 20 per-persona files:

```text
dialogues/traj_001.jsonl … traj_020.jsonl
gold/traj_001.jsonl … traj_020.jsonl
```

Load all personas via the config, or a single persona by file:

```python
from datasets import load_dataset

dlg = load_dataset(
    "hangyeul-lee/life-event-benchmark-v2-dialogues",
    "dialogues",
    split="train",
)
gold = load_dataset(
    "hangyeul-lee/life-event-benchmark-v2-dialogues",
    "gold",
    split="train",
)
```

Join `dialogues` ↔ `gold` on `(trajectory_id, session_id)`.

### `dialogues`

Answer-key-free conversation fields such as `persona_id`, `session_id`,
`trajectory_id`, chronological position, `turns`, `model`, and `provider`.

### `gold`

Labels and generation metadata: `session_type`, `mapped_action`, `financial_task`,
event links/status, `cue_annotations`, `action_resolution`, `plan`, and
`generation_metadata`.

## Counterfactual filler bank v1

The signal-ablation experiment holds a canonical prefix checkpoint fixed and
replaces selected lifecycle-evidence turns with neutral reserve dialogue. The bank
is stored separately from the canonical timeline:

```text
counterfactual_fillers/v1/
├── sessions/fillers_traj_001.jsonl … fillers_traj_020.jsonl
├── plans/plans_traj_001.jsonl … plans_traj_020.jsonl
├── audit/
├── filler_generation_manifest.json
└── artifact_manifest.json
```

Each persona has 20 fillers (`CF001`–`CF020`). A filler:

- has `source_kind="synthetic_reserve"` and `month_index=null`;
- contains exactly eight alternating user/assistant turns;
- uses the same persona's dialogue style but no life-state facts;
- contains only an unlinked, information-only routine banking task;
- has no lifecycle event or memory update;
- is generated by `claude-sonnet-5` and retains per-batch generation metadata.

Load the filler sessions through the dataset config:

```python
fillers = load_dataset(
    "hangyeul-lee/life-event-benchmark-v2-dialogues",
    "counterfactual_fillers",
    split="train",
)
assert len(fillers) == 400
```

For exact experimental reconstruction, use the repository fetch/pipeline scripts.
They preserve per-persona files and can pin the dataset commit through
`HF_DIALOGUE_REVISION`.

## Quality

The canonical production personas passed the repository's dialogue QA pipeline.
The counterfactual bank passed its deterministic frozen-plan audit:

- 20 persona files and 400/400 expected fillers;
- exactly 20 fillers per persona and two realizations per neutral task;
- no lifecycle/memory cue, personal lookup result, cross-persona donor, or contract
  violation;
- all 451 terminal events are maskable with zero filler exclusions.

See `counterfactual_fillers/v1/audit/` and `artifact_manifest.json` for decisions,
counts, and SHA256 hashes.

## Caveats

- Fully synthetic: no dialogue represents a real customer.
- Counterfactual fillers are evaluation controls, not extra chronological sessions.
- Filler generation is not rerun during evaluation; consumers should fetch and pin
  the frozen v1 artifact.
- The filler bank controls missing evidence. A separate placebo arm is needed to
  isolate any residual filler-style effect.
