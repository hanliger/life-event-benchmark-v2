다음은 한 고객의 은행 상담 세션 이력입니다. 세션은 시간순으로 정렬되어 있고, 각 세션은 `[세션 D###]` 식별자와 대화 발화로만 구성됩니다.

당신의 과제는 이 이력에서 실제로 일어난 생애 사건(Life Event)을 모두 찾고, 각 사건이 실제로 일어났음을 처음으로 분명히 확인해 주는 세션 하나를 짝지어 보고하는 것입니다.

## 판단 규칙

- 사건의 개수는 알려져 있지 않습니다. 0개일 수도, 1개일 수도, 여러 개일 수도 있습니다.
- 같은 종류의 사건이 서로 다른 시점에 여러 번 실제로 일어날 수 있습니다. 각 발생을 별도의 레코드로 보고하세요.
- 실제로 일어난 사건만 보고하세요.
- 약한 단서나 막연한 암시만 있는 사건은 아직 일어난 것이 아닙니다. 보고하지 마세요.
- 앞으로의 계획이나 예정만 확인된 사건은 아직 일어난 것이 아닙니다. 보고하지 마세요.
- 예정되었다가 취소된 사건은 일어나지 않은 것입니다. 보고하지 마세요.
- 사건과 무관한 일상적인 금융 업무 세션은 사건의 근거가 아닙니다.
- 사건이 일어난 것처럼 보이게 하지만 실제로는 아무 사건도 확인되지 않는 세션이 섞여 있습니다. 이런 세션을 고르지 마세요.
- 이미 일어난 사건의 후속 처리를 다루는 세션, 또는 과거 사실을 뒤늦게 언급하기만 하는 세션은 발생을 처음 확인해 주는 세션이 아닙니다.
- 사건 라벨을 틀리게 붙이면 정밀도가 떨어집니다.
- 근거 세션을 잘못 고르면 정밀도가 떨어집니다.
- 뒷받침되지 않는 짝을 덧붙이면 정밀도가 떨어집니다.
- 실제로 일어난 사건의 짝을 빠뜨리면 재현율이 떨어집니다.
- 어떤 구체적인 사건이 포괄적인 결과를 함의하는 경우, 그 포괄적인 사건이 따로 독립적으로 확인되지 않는 한 구체적인 사건만 보고하세요.

## 출력 형식

설명이나 이유 없이 아래 구조의 JSON만 출력하세요.

```json
{
  "pairs": [
    {
      "event_id": "<EVENT_ID>",
      "evidence_session_id": "<VISIBLE_SESSION_ID>"
    }
  ]
}
```

- `event_id`: 위 목록에 있는 식별자를 그대로 사용하세요. 한국어 라벨이나 임의의 문자열을 쓰지 마세요.
- `evidence_session_id`: 위 이력에 실제로 존재하는 `D###` 형식의 세션 ID 하나. 한 레코드에 세션을 두 개 이상 넣지 마세요.
- 레코드에는 위 두 개의 필드만 넣으세요.
- 레코드를 `evidence_session_id`, 그다음 `event_id` 순서로 정렬하세요.
- 실제로 일어난 사건이 하나도 없으면 다음을 그대로 출력하세요.

```json
{"pairs": []}
```
